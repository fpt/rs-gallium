# Audio: the model is played a spoken sentence and asked to transcribe it.
# `@audio:<path>` attaches a clip to the turn, the same way `@image:` does.
#
# The codeword is nowhere in the prompt, so a model that did not receive the
# audio has nothing to transcribe — which is the whole test.
#
# Passes only where audio actually reaches a model: the llama.cpp backend with
# an `mmprojPath` whose projector has an audio encoder. The OpenAI and candle
# backends refuse the turn rather than answering about a clip they never got.
#
# Transcription rather than "name the pitch of this tone", which was the first
# version and which nothing passes: Gemma 4 12B demonstrably *heard* a 613 Hz
# tone and still answered "440". Pitch estimation is not what these models do.
#
# The wording is load-bearing and was measured, not guessed. "Transcribe the
# speech in this audio clip" makes Gemma 4 E4B answer "you have not provided
# one" — 3 runs out of 3, with the audio demonstrably encoded into the prompt
# (1836 tokens against ~700 for text alone). Dropping the words "in this audio
# clip" transcribes correctly, also 3 out of 3. Keep it short.
@audio:speech.wav Transcribe this audio exactly. Reply with only the transcription.
